# QBO AI Controller Agent

A multi-company, controller-grade accounting intelligence platform that connects directly to QuickBooks Online via the official API. Designed to work with multiple different QBO companies in complete isolation — one company = one isolated accounting workspace.

## What It Does

- **Real-time QBO data sync** — pulls live data from QuickBooks Online via OAuth 2.0
- **Accounting health score** — 0–100 weighted score across 10 accounting categories
- **Automated issue detection** — identifies uncategorized transactions, undeposited funds, opening balance equity, AR/AP aging problems, and more
- **Journal entry approval workflow** — propose → approve → execute in QBO → verify → document
- **24-step month-end close checklist** — interactive controller close process
- **Audit readiness report** — area-by-area audit prep with scoring
- **Financial reports** — Balance Sheet, P&L, AR/AP aging with controller-level annotations
- **Immutable change log** — every QBO modification recorded with approval trail
- **Multi-company portfolio dashboard** — manage unlimited QBO companies

**Default mode: READ-ONLY.** Write actions (journal entries) require explicit approval before execution. The agent never automatically modifies QBO data.

## Setup

### 1. Prerequisites

- Python 3.9 or higher
- A QuickBooks Online company (sandbox or production)
- An Intuit Developer account (free)

### 2. Get QBO API Credentials (Free)

1. Go to [https://developer.intuit.com](https://developer.intuit.com) and sign in with your Intuit/QBO account
2. Click **"Create an app"** → select **"QuickBooks Online and Payments"**
3. Name your app (e.g., "My Controller Agent")
4. In your app settings, go to **"Keys & credentials"**
5. Copy your **Client ID** and **Client Secret**
6. Under **"Redirect URIs"**, add: `http://localhost:8000/qbo/callback`
7. Save

> **Sandbox vs Production:**
> - Sandbox: Use your app's sandbox credentials. QBO provides a test company at [qbo.intuit.com/redir/testdrive](https://qbo.intuit.com/redir/testdrive)
> - Production: Use your app's production credentials after Intuit approves your app (or use development access)

### 3. Install

```bash
# Clone or copy the project directory
cd qbo_controller

# Run the setup script (Linux/macOS)
chmod +x setup.sh
./setup.sh
```

Or manually:

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# Edit .env with your credentials (see below)
```

### 4. Configure `.env`

```bash
# Required — from Intuit Developer Console
QBO_CLIENT_ID=ABcdef123...
QBO_CLIENT_SECRET=xyz789...

# QBO environment: "sandbox" for testing, "production" for live data
QBO_ENVIRONMENT=sandbox

# Auto-generated by setup.sh — or generate manually:
# python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
ENCRYPTION_KEY=your_fernet_key_here

# Auto-generated by setup.sh — or use any random 32+ char string
SECRET_KEY=your_secret_key_here

# Leave defaults for local development
QBO_REDIRECT_URI=http://localhost:8000/qbo/callback
DATABASE_URL=sqlite:///./qbo_controller.db
APP_HOST=0.0.0.0
APP_PORT=8000
DEBUG=false
```

### 5. Start the App

```bash
# Activate virtual environment first
source venv/bin/activate

# Start
python run.py

# Or with uvicorn directly
uvicorn app.main:app --reload
```

Open [http://localhost:8000](http://localhost:8000) in your browser.

## Connecting a QBO Company

1. Open the dashboard at `http://localhost:8000`
2. Click **"Connect QuickBooks Company"**
3. Enter your company name (for display purposes)
4. Click **"Connect to QuickBooks Online"**
5. You'll be redirected to Intuit's authorization page — sign in and approve
6. You're redirected back to your company workspace
7. Click **"Sync from QBO"** to pull all data

Repeat for each QBO company you want to manage. Each company is completely isolated.

### Company Isolation

Every database table includes `realm_id` (QBO's unique company identifier). Every query is filtered by `realm_id`. The `QBOClient` raises `ValueError` if `realm_id` is missing. Cross-company data access is architecturally impossible.

### Token Security

OAuth tokens are encrypted with Fernet symmetric encryption before storage. Tokens are never logged or stored in plaintext. The encryption key lives only in `.env` (never in the database).

### Approval Workflow

```
READ-ONLY → DETECT → ANALYZE → RECOMMEND → REVIEW → APPROVE → EXECUTE → VERIFY → DOCUMENT
```

Journal entries follow this exact pipeline. "Execute" calls the QBO API and creates the entry. All steps are logged in the immutable change log.

## Company Health Score

The 0–100 health score is weighted across 10 accounting categories:

| Category | Weight | What It Checks |
|---|---|---|
| Bank Reconciliation | 20 pts | Unreconciled bank transactions, old uncleared items |
| Balance Sheet Integrity | 18 pts | BS equation, Opening Balance Equity, undeposited funds |
| P&L Integrity | 10 pts | Uncategorized income/expense, revenue recognition |
| AR Status | 10 pts | 90+ day receivables, AR aging health |
| AP Status | 8 pts | Overdue payables, AP aging |
| Credit Card Reconciliation | 8 pts | Unreconciled CC transactions |
| Uncategorized Transactions | 10 pts | Ask My Accountant, uncategorized items |
| Payroll | 6 pts | Payroll liability reconciliation |
| Sales Tax | 5 pts | Sales tax payable, filing status |
| Equity Review | 5 pts | Opening Balance Equity, distributions |

**Score Ranges:** 90–100 = Excellent · 75–89 = Good · 60–74 = Fair · 40–59 = Poor · 0–39 = Critical

## Security Notes

- **Never stores QBO passwords** — uses OAuth 2.0 only
- **Tokens encrypted at rest** — Fernet symmetric encryption
- **CSRF protection** — cryptographic state parameter in OAuth flow
- **Multi-tenant isolation** — realm_id enforced on every query
- **Read-only by default** — write actions require explicit human approval
- **Immutable audit log** — every action recorded and cannot be deleted

## Deploying Beyond Localhost

To use with a live QBO company:

1. Deploy to a server with HTTPS (required by Intuit for production)
2. Update `QBO_REDIRECT_URI` in `.env` to your HTTPS URL
3. Add the HTTPS redirect URI in Intuit Developer Console
4. Set `QBO_ENVIRONMENT=production`
5. Change `APP_HOST=0.0.0.0` and set `DEBUG=false`
6. Use a production database (PostgreSQL recommended — change `DATABASE_URL`)
7. Use a proper secret store for `ENCRYPTION_KEY` and `SECRET_KEY` (not `.env`)

For production, consider:
- PostgreSQL instead of SQLite
- Redis for OAuth state storage (replace `_oauth_states` dict in `main.py`)
- NGINX or Caddy as reverse proxy with automatic HTTPS
- Environment variables via your platform's secret manager
